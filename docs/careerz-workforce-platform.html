Careerz Group — Workforce Platform

Full-Stack Architecture, Agentic Engineering, and Rapid Delivery

The Project

The objective was to extend an existing assessment platform into a workforce management application that organizations could use to evaluate candidates and employees against position requirements.

This introduced a different set of challenges from administering assessments. Organizations needed to manage positions, define requirements, compare individuals, review results, and make informed decisions while maintaining appropriate access boundaries.

I was responsible for the architecture, technical direction, and hands-on engineering.

Using AI coding agents extensively throughout development, I delivered the initial Workforce Portal to production in approximately three weeks.

Building on an Existing Platform

One of the early architectural decisions was to extend the existing system rather than duplicate its assessment capabilities.

The platform already maintained user identities and assessment results. The new workforce functionality needed to introduce organizations, memberships, positions, candidate associations, and reporting without creating a separate system of record for information that already existed.

The resulting architecture uses a React and TypeScript frontend with a TypeScript/Express API, PostgreSQL, and Prisma.

The application supports organizational administration, position management, candidate and employee comparisons, configurable matching criteria, and reporting.

An important consideration was separating access to workforce information from the ability to participate in an assessment. Organizational permissions and assessment participation are distinct responsibilities, with access decisions enforced by the backend.

This allowed the new functionality to build on existing capabilities while preserving clear ownership and authorization boundaries.

Agentic Engineering in Practice

A distinguishing aspect of this project was the development approach.

Rather than treating AI coding agents as unrestricted developers, I established architectural expectations, coding standards, and implementation boundaries to guide their work.

The development process emphasized requirements, API contracts, data modeling, and verification. Agents accelerated implementation, while architectural decisions, consequential changes, and responsibility for the delivered system remained under my control.

Automated testing supported important workflows, particularly around access control, data relationships, candidate participation, and reporting.

The objective wasn't simply to produce code faster. It was to use agents to increase engineering capacity while maintaining a coherent architecture and a system that could continue evolving.

Engineering Decisions

Several decisions helped keep the implementation manageable.

Reuse existing capabilities. The workforce platform builds on established assessment identities and results rather than maintaining competing implementations.

Keep responsibilities clear. Organization membership, workforce participation, and assessment access are separate concepts, reflected in both the data model and authorization logic.

Favor straightforward architecture. A modular application and shared API provided the required functionality without introducing distributed services or unnecessary orchestration.

Use consistent business logic. Matching and reporting share deterministic calculations, helping maintain consistent results across different application workflows.

Build for continued development. The initial release established a foundation that could be extended with additional administrative, reporting, and workforce capabilities.

Outcome

The initial Workforce Portal reached production in approximately three weeks, demonstrating the practical use of agentic engineering to deliver a substantial business application.

Development continued beyond that release, with additional functionality and refinements.

For me, the project demonstrates how architectural direction, thoughtful boundaries, and AI-assisted implementation can work together.

The agents accelerated execution, but engineering judgment and responsibility for the result remained human.

Technical Stack

  • Frontend: React, TypeScript, Vite, TanStack Query
  • Backend: Node.js, TypeScript, Express
  • Database: PostgreSQL, Prisma
  • API: REST, OpenAPI, request validation
  • Testing: Mocha, Chai, Supertest, Vitest, React Testing Library, MSW
